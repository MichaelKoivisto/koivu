### Transforming S-LLVM IR to a Formal Internal LLVM IR AST

**Status:** Developer Notes  

**Component:** Backend  

When the compiler transitions from pretty-printing `.ll` text files to native machine-code generation, the dynamic list outputs generated by the `s-llvm-ir` constructors must be parsed into a formal, structured **LLVM IR Abstract Syntax Tree (AST)** inside the compiler's memory. 

This transformation validates the syntactic boundaries of the IR and constructs an explicitly typed graph suitable for a machine-code backend pass to traverse.

#### The AST Node Formats
Inside the compiler memory, nodes are structured as tagged representations ensuring clear separation between opcodes, types, and operands:

1. **Instruction Node:** `(ast-instr <opcode-sym> <dest-node> <type-node> <op1-node> <op2-node>)`
2. **Value Node:** `(ast-val <val-type> <symbol-or-literal>)` where `<val-type>` is `'reg`, `'global`, or `'literal`.
3. **Block Node:** `(ast-block <label-sym> <instruction-nodes-list>)`

---

#### The AST Transformation Pass
The transformation layer acts as an internal structural parser. It recursively walks the list structures emitted by your codebase and yields a formal AST tree:

```scheme
;; Inside (koivu backend syntax llvm-ir) 
;; Maps standard s-llvm-ir lists into a formal, unvalidated LLVM IR AST graph
(define (s-llvm-ir->formal-ast node-list)
  (let loop ((nodes node-list)
             (ast-accum '()))
    (cond
      ((null? nodes) (reverse ast-accum))
      
      (else
       (let ((current (car nodes)))
         (cond
           ;; 1. Transform Assignment Statements
           ((eq? (car current) 'assign)
            (let* ((dest-reg   (cadr current))  ; e.g., %res
                   (expr-block (caddr current)) ; e.g., (add i32 %a %b)
                   (opcode     (car expr-block))
                   (type       (cadr expr-block))
                   (op1        (caddr expr-block))
                   (op2        (cadddr expr-block)))
              
              (let ((formal-node 
                     (list 'ast-instr
                           opcode
                           (list 'ast-val 'reg type dest-reg)
                           type
                           (list 'ast-val 'reg type op1)
                           (list 'ast-val 'reg type op2))))
                (loop (cdr nodes) (cons formal-node ast-accum)))))
           
           ;; 2. Transform Terminator Statements
           ((eq? (car current) 'ret)
            (let ((type (cadr current))
                  (val  (caddr current)))
              (let ((formal-node
                     (list 'ast-instr
                           'ret
                           'void ; No destination register
                           type
                           (list 'ast-val 'reg type val)
                           'none)))
                (loop (cdr nodes) (cons formal-node ast-accum)))))
           
           (else (error "Unknown s-llvm-ir layout shape during AST generation pass."))))))))
```

#### The Resulting Internal AST Structure (Mental Model)
When this pass completes, a basic addition block is represented as a formal, nested tree array in memory, waiting to be consumed by your target code generator:

```scheme
;; The formal, unvalidated LLVM IR AST structure in compiler memory:
'((ast-instr add 
             (ast-val reg i32 %res) 
             i32 
             (ast-val reg i32 %a) 
             (ast-val reg i32 %b))
  (ast-instr ret 
             void 
             i32 
             (ast-val reg i32 %res) 
             none))
```
